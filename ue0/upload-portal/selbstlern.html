1. Warum überhaupt?

Selbst wenn ein Amt schon ein modernes Webformular anbietet, füllen viele Bürgerinnen und Bürger Anträge immer noch so aus, wie sie es seit Jahren tun: das offizielle PDF herunterladen, am Computer oder per Hand ausfüllen, scannen, mailen. Im Amt landet dieser Eingang als Mail-Anhang — und dort beginnt der Aufwand.

Was heute typisch passiert:
  1. Eingang als E-Mail-Anhang
  2. Mensch im Amt öffnet, druckt aus, heftet in die Akte
  3. Mensch tippt alle Felder ins Fachverfahren ab
  4. Fehlerquellen: Zahlendreher, übersehene Felder, unleserliche Handschrift

Die Idee von UE0

UE0 ist eine sehr milde Innovation: der/die Bürger:in muss nichts Neues lernen, sondern lädt nur statt einer Mail das PDF in ein Web-Portal hoch. Im Hintergrund liest eine KI das PDF und füllt alle Felder direkt ins Webformular vor — Bürger:in bestätigt nur noch.

💡 Kerngedanke: „Reifegradstufe 0" heißt nicht „primitiv", sondern: der Eingang bleibt das, was die Bürger:in kennt — die digitale Verbesserung passiert unsichtbar dazwischen.

2. Konzept & Architektur

Die Pipeline besteht aus vier klar getrennten Schichten:

SCHICHT 1 · FRONTEND
Upload-UI mit Drag & Drop
Zwei Boxen (Pflichtfeld „Hauptantrag" rot, optional „Anlage 1" grau), Drag & Drop, MIME-Check, baut FormData, sendet als Multipart-POST.
src/views/fb-upload.ts
SCHICHT 2 · EDGE FUNCTION
Validierung & Storage-Upload
Validiert MIME (nur PDF) + Größe (≤10 MB), legt das PDF im privaten Supabase-Storage-Bucket ab, erzeugt einen Tracking-Eintrag mit unguessable UUID.
supabase/functions/upload-antragspdf/index.ts
SCHICHT 3 · DATENBANK
Tracking-Tabelle & Trigger
Tabelle apl.antrag_einreichung hält Status + Felder. DB-Trigger feuert per pg_notify einen HTTP-POST an n8n. RLS: anon darf insert + eigenen Status lesen, nichts anderes.
supabase/migrations/047_ue0_pdf_einreichung.sql
SCHICHT 4 · n8n-PIPELINE
KI-OCR mit Claude Vision
11 Nodes: Storage-Download → Base64 → Claude Vision mit JSON-Schema-Prompt → JSON parsen → Defaults → UPDATE Tracking-Tabelle mit status='fertig'. IF-Switch für optionale Anlage 1 (Wochenplan).
supabase/webhooks/n8n-ue0-pdf-ocr.json

4. Vorteile, Grenzen, DSGVO

Was UE0 gewinnt

AspektPDF-Mail heuteUE0
EingangswegE-Mail/Briefstrukturierter Upload
Erfassungsfehlerhoch (manuell)niedrig (Vision-OCR)
Doppelte Erfassungja (Bürger + Amt)nein (Bürger bestätigt)
Status für Bürger:in„warte auf Antwort"Tracking + Auto-Redirect
Akzeptanzhürdeniedriggleich niedrig (PDF bleibt)

Was UE0 nicht löst

  • Bürger:in braucht weiterhin das PDF
  • Keine Live-Validierung beim Ausfüllen (das macht UE1)
  • Keine Mehrsprachigkeit beim Ausfüllen (PDF ist deutsch)
  • OCR-Restfehler bleiben möglich — UE1 ist der Kontroll-Schritt
  • Keine semantische Prüfung gegen die Förderrichtlinie (UE3)
  • Keine automatisierte Bescheid-Erstellung (UE3)

⚖️ DSGVO & AI Act

Claude Vision verarbeitet die PDFs in den USA. Für eine echte Verwaltungs-Anwendung müsste:

  • DPF/AVV mit Anthropic + TIA durchgeführt sein, ODER
  • EU-gehosteter Vision-LLM verwendet werden (z.B. Mistral Pixtral via Scaleway/Bedrock-EU), ODER
  • self-hosted Vision-Modell (Llama 3.2 Vision via LM Studio)

Die Demo nutzt Anthropic für Lehrzwecke — der Disclaimer im Footer macht das offen.

Verständnis-Quiz

Vier Fragen, je 1 richtige Antwort. Klicke auf eine Option, du bekommst sofort Feedback.

1. UE0 schreibt die extrahierten Felder direkt in welche Tabelle?

  • apl.antraege
  • apl.bescheide
  • apl.antrag_einreichung (Tracking-Tabelle)
  • auth.users

2. Welche Schicht kümmert sich um den eigentlichen OCR-Schritt?

  • Das Frontend
  • Die Edge Function
  • Der DB-Trigger
  • Der n8n-Workflow

3. Warum nutzt UE0 einen Tracking-Eintrag mit UUID statt eines Auth-Logins?

  • Damit Bürger:in den Status ohne Anmeldung wieder aufrufen kann
  • Weil Supabase keinen Auth-Modus für anon-User unterstützt
  • Weil das PDF sonst dauerhaft öffentlich wäre
  • Aus Performance-Gründen

4. Welche Verbesserung bringt UE0 dem Amt am stärksten?

  • Bessere Bescheids-Qualität
  • Wegfall der manuellen Felder-Erfassung beim Posteingang
  • Mehrsprachige Anträge
  • Automatische Bewilligung

Lösungen werden direkt beim Klick angezeigt — du musst nichts „abschicken".

Praxis-Aufgaben (Vertiefung)

Wenn du selber Hand anlegen willst — vier Aufgaben mit steigender Schwierigkeit. Detaillierte Anleitung in 04-aufgaben.md.

A — OCR-Prompt verbessern · 15 Min · Schwierigkeit ⭐

Den Claude-Prompt so anpassen, dass leere Felder als null zurückkommen, nicht als 0. Bonus: mit Handschrift-Demo-PDF testen.

B — Neues Anlagen-Feld „Programm-Flyer" · 60 Min · Schwierigkeit ⭐⭐

Eine dritte Upload-Box hinzufügen und durch alle 4 Schichten ziehen (Frontend → Edge Function → DB → n8n).

C — Polling durch Supabase Realtime ersetzen · 45 Min · Schwierigkeit ⭐⭐

Statt alle 3 s pollen → Postgres-Changes-Channel abonnieren. Polling als Fallback behalten.

D — Eigene Supabase-Instanz · 2–3 h · Schwierigkeit ⭐⭐⭐

Komplettes Setup nachvollziehen: eigenes Supabase-Projekt, Migrationen 001–067 ausführen, Edge Function deployen, n8n-Workflow importieren, Demo-PDF hochladen. Lerne dabei die ganze Architektur kennen.
