## FB IV — Struktur- und Schwerpunktförderung der Seniorenarbeit

**Quelle Website:** „Formlos"
**PDF im Repo:** keines (es gibt kein offizielles Antragsformular).

### Konsequenz für unser System
- UE1 (Bürger): kein strukturiertes Formular, sondern
  - Antragsteller-Block (wie FB I-III)
  - Bank-Block
  - **PDF-Upload** des eigenen formlosen Antrags + beliebige Anlagen
  - (Optional: Kurzbeschreibung als Freitext für die KI-Vor-Klassifikation)
- UE3 (Sachbearbeitung): zeigt den hochgeladenen PDF + Antragsteller-Daten,
  ohne erfundene Strukturfelder

## Konkrete Halluzinations-Befunde (heute aufgedeckt)

| Erfundenes Feld | Wo | Status |
|---|---|---|
| `hausnummer` als separates Feld | UE1 + DB | PDF hat nur „Straße" — Trennung ist DB-Convenience, nicht im PDF. Kann bleiben (defensive Datenmodellierung), aber Label im PDF-konformen Mode optional |
| FB I `drittmittel_jsonb` als strukturierte Liste | UE1 + DB | PDF hat nur Freitext „Beantragte Drittmittel". Strukturierung ist UX-Gewinn, aber **kein PDF-Feld**. |
| FB I `andere_mittel_jsonb` als strukturierte Liste | UE1 + DB | Wie oben, Freitext im PDF. |
| FB II Helfer `name` und `vorname` getrennt | UE1 + DB | PDF kombiniert sie zu „Name, Vorname". Getrennt ist UX-Gewinn, kein Erfindungs-Problem. |
| FB I `beantragte_summe_euro` | (alt) | Existiert NICHT als eigenes Feld im FB-I-PDF — nur Personalkosten + Sachkosten. Die „beantragte Summe" ergibt sich aus deren Summe. ✅ aktuell sauber. |
| FB III Variante D `d_ehrenamt_personen_jsonb` | aktuell UE1 + DB | PDF hat genau 4 Person-Slots (1-4). Aktuell als jsonb-Array → konform, aber Struktur nicht 1:1 zum PDF (4 separate Felder). Akzeptable Vereinheitlichung. |
| FB IV `fb_iv_freitext`-Tabelle mit `vorhaben_titel`, `kurzbeschreibung`, `geplante_massnahmen`, `beantragte_summe_euro`, `laufzeit` | aktuell DB | **DAS IST ERFUNDEN**, weil FB IV laut Würzburg.de formlos ist. Korrigieren: FB-IV-Antrag = Antragsteller + Bank + PDF-Upload, keine strukturierten Vorhaben-Felder. |

## Pflicht-Restoration nach diesem Audit

1. **UE1 + DB:** FB IV von „strukturiertes Freitext-Formular" auf „formloser PDF-Upload" umstellen
2. **`@dv/antrag-renderer`:** FB-IV-Schema anpassen — statt Vorhaben/Kurzbeschreibung-Felder nur „Hochgeladenes Dokument anzeigen"
3. **DB-Migration:** `fb_iv_freitext`-Spalten als optional / nullable markieren (keine Datenverluste für bestehende Demo-Anträge), neue Spalte `fb_iv_dokument_path` für die Upload-Referenz
4. **Ontologie:** Förderrichtlinie-Abschnitt für FB IV in `ahp_norm_statements` als „Bedingungen für Schwerpunktförderung" hinzufügen
