1. Warum nicht einfach ein Mail-Postfach?

Heute landet ein Antrag im Mail-Postfach des Amtes — und damit beginnt die eigentliche Verwaltungs-Schmerzpunkte:

  • Mehrere Sachbearbeitende greifen drauf zu — niemand weiß wer was bearbeitet hat
  • Statusänderungen in Excel-Listen oder Akten-Deckel-Notizen
  • Bürger:in bekommt keine Eingangsbestätigung → unsicher
  • Bei Rückfragen: „Da müsste ich mal nachschauen…"

UE2 ist die erste Reifegradstufe mit echter Verwaltungs-IT: geteilte Realtime-Inbox, Workflow als Datenmodell in der DB, automatische Eingangsbestätigung in 4 Sprachen, vollständiger Audit-Trail.

💡 Kernbotschaft: Diese Stufe ist nicht KI-getrieben — sie löst nur das, was eine klassische Workflow- Engine kann. Aber sie eliminiert dabei den gesamten „Wer-hat-was- gemacht?"-Schmerz.

2. Magic-Link-Auth + Allowlist

Sachbearbeitende loggen sich per Magic-Link ein: E-Mail eingeben, auf den Link in der Mail klicken, fertig. Keine Passwörter, keine Phishing-Angriffe auf Credentials. 

1. POST /auth/v1/otp { email }
2. GoTrue → SMTP → Mail mit Token-Link
3. Klick → /auth/callback#access_token=...
4. setSession() → localStorage
5. allow_email-Lookup (RLS: nur authenticated darf lesen,
   eigene Zeile via auth.jwt())
6. Wenn Match → /inbox
7. Wenn kein Match → zurück zu /login
💡 Live-Diagnose-Card auf /login zeigt alle 5 Schritte mit ✓/✗-Status. Lektion gelernt am 2026-05-30 nach 5 Stunden Hin-und-Her: sichtbare Diagnose ist Gold wert.

3. Workflow-Engine + Audit-Trail

Erlaubte Status-Übergänge

eingegangen     → in_pruefung
in_pruefung     → eingegangen | zurueckgewiesen | bewilligt | abgelehnt
zurueckgewiesen → in_pruefung
bewilligt       → (final)
abgelehnt       → (final)

Diese Regeln stehen in apl.workflow_transition und werden zweifach geprüft:

  1. Frontend (src/lib/workflow.ts): zeigt nur erlaubte Übergänge im Status-Select
  2. Postgres-Trigger: blockiert unerlaubte Übergänge auch bei DevTools-Manipulation

Audit-Trail in apl.antrag_history

event_at2026-05-30 14:23:15 UTC
user_emailsachbearbeiter@stadt.wuerzburg.de
event_typestatus_change
alt_statuseingegangen
neu_statusin_pruefung
kommentar„Wartet auf Helferliste"

Trigger-basiert: jeder UPDATE auf apl.antraege erzeugt automatisch einen Eintrag. Frontend muss nichts tun.

⚠️ Grenze: Wer direkt mit service_role arbeitet, bypasst die Trigger. Echte Revisionssicherheit bräuchte WORM-Storage (Write-Once-Read-Many).

4. Realtime-Inbox & signed Downloads

Realtime via Supabase-Channels

Inbox abonniert postgres_changes-Channel auf apl.antraege: 

supabase
  .channel('antraege-changes')
  .on('postgres_changes',
    { event: '*', schema: 'apl', table: 'antraege' },
    (payload) => mergeAntragInState(payload))
  .subscribe();

Sachbearbeitende A ändert Status → Sachbearbeitende B sieht es sofort in ihrer offenen Inbox, ohne Reload.

Signed URLs für Anlagen-Downloads

Storage-Bucket antragsbelege ist private. Wenn jemand eine Anlage runterladen will: 

const { data } = await supabase.storage
  .from('antragsbelege')
  .createSignedUrl(`${antragId}/${dateiname}`, 600); // 10 min

Die generierte URL ist 10 Minuten gültig. Niemand kann den Storage-Pfad direkt aufrufen ohne Token.

Verständnis-Quiz

1. Was passiert, wenn jemand mit DevTools eine ungültige Status-Änderung sendet?

  • Geht durch, weil Browser-State nicht prüfbar ist
  • Wird vom Frontend abgelehnt
  • Wird vom Postgres-Trigger abgelehnt (Defense-in-Depth)
  • Wird im Audit-Log markiert, aber gespeichert

2. Warum Magic-Link statt Passwort?

  • Weil Supabase nichts anderes unterstützt
  • Keine Phishing-anfälligen Credentials, keine Passwort-Verwaltung
  • Aus UX-Gründen (schöner)
  • Aus Performance-Gründen

3. Was ist NICHT im Audit-Trail von apl.antrag_history?

  • Der konkrete Feld-Wert (z.B. „neue IBAN: DE12...")
  • Wer (E-Mail des Sachbearbeitenden)
  • Wann (Timestamp)
  • Was (alt/neu Status)

4. Warum brauchen Anlagen-Downloads signed URLs?

  • Aus Performance-Gründen
  • Damit der Bürger sie wiederfinden kann
  • Weil das Frontend keine direkte Storage-Auth hat
  • Damit Storage-Pfade nicht direkt öffentlich abrufbar sind
